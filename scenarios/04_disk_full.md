# 第4弾：ディスク容量不足の再現・原因調査・復旧

## 1. 検証目的

Linuxサーバでディスク容量が不足した際に、どのようなエラーが発生するのかを確認する。

今回は、サーバ全体のディスクを満杯にするのではなく、**100MBの検証用ディスクイメージを作成し、その中だけで容量不足を再現する。**

障害発生後は、使用量の調査、不要なファイルの削除、書き込みの復旧確認まで実施する。

## 2. 検証環境

- OS：Ubuntu Server 24.04
- 仮想環境：VirtualBox
- 対象サーバ：tokyo
- 検証用イメージ：`/var/tmp/disk-lab.img`
- マウント先：`/mnt/disk-lab`
- ファイルシステム：ext4

※ 自宅の仮想マシン上で実施した検証。

## 3. 正常状態の確認

まず、サーバのディスク使用量を確認する。

```bash
df -h
```

今回の検証では、ルートファイルシステムは約25GBで、使用率は約24%だった。

## 4. 検証用ディスクの準備

検証用のマウント先を作成する。

```bash
sudo mkdir -p /mnt/disk-lab
```

100MBの検証用ディスクイメージを作成する。

```bash
sudo truncate -s 100M /var/tmp/disk-lab.img
```

ext4ファイルシステムを作成する。

```bash
sudo mkfs.ext4 /var/tmp/disk-lab.img
```

ループバックデバイスを使ってマウントする。

```bash
sudo mount -o loop /var/tmp/disk-lab.img /mnt/disk-lab
```

マウント後の容量を確認する。

```bash
df -h /mnt/disk-lab
```

実際の検証では、利用可能な容量が約83MBと表示された。

これは、ファイルシステムの管理領域などがあるため、イメージの100MBすべてを自由に使えるわけではないことを示している。

## 5. 容量不足の再現

検証用ディスク内に50MiBのファイルを作成する。

```bash
sudo dd if=/dev/zero of=/mnt/disk-lab/test-data.bin bs=1M count=50
```

続いて、40MiBのファイル作成を試みる。

```bash
sudo dd if=/dev/zero of=/mnt/disk-lab/overflow.bin bs=1M count=40
```

実際の検証では、次のエラーが発生した。

```text
No space left on device
```

これは、書き込み先のファイルシステムに空き容量がなくなったことを示している。

## 6. 原因の切り分け

ディスク使用率を確認する。

```bash
df -h /mnt/disk-lab
```

実際の検証では、使用率が100%になった。

次に、どのファイルが容量を使用しているのか調査する。

```bash
sudo du -h /mnt/disk-lab/test-data.bin /mnt/disk-lab/overflow.bin
```

実際の検証では、約50MBと約38MBのファイルが容量を使用していることを確認した。

`df` はファイルシステム全体の使用状況、`du` は指定したファイルやディレクトリの使用量を調べる際に役立つ。

## 7. 修正と復旧

容量不足を再現するために作成した `overflow.bin` を削除する。

```bash
sudo rm /mnt/disk-lab/overflow.bin
```

※ 削除する前に、対象が検証用ファイルであることを確認する。

空き容量が戻ったか確認する。

```bash
df -h /mnt/disk-lab
```

実際の検証では、使用率が約61%まで下がった。

その後、検証用ディスク内でファイルの作成・書き込み・読み取りができることを確認した。

つまり、容量不足が解消され、再び書き込み可能な状態になった。

## 8. 検証環境の後片付け

マウントを解除する。

```bash
sudo umount /mnt/disk-lab
```

マウント解除後、検証用イメージとディレクトリを削除する。

```bash
sudo rm /var/tmp/disk-lab.img
sudo rmdir /mnt/disk-lab
```

※ イメージの削除は、マウント解除を確認してから実施する。

実際の検証では、後片付けまで完了した。

## 9. 今回の検証で学んだこと

- `No space left on device` は、書き込み先の容量不足を示すエラー
- `df` でファイルシステムの使用率を確認できる
- `du` で容量を使用しているファイルを調査できる
- 容量不足の原因となったファイルを削除すると空き容量を回復できる
- 復旧後は、使用率だけでなく書き込み可能かどうかも確認する
- ループバックデバイスを使えば、サーバ全体への影響を抑えて容量不足を検証できる

## 10. 注意事項

本検証は、専用のディスクイメージ内だけで容量不足を再現したものである。

本番環境でディスクを意図的に満杯にしたり、調査せずにファイルを削除したりしてはいけない。

容量不足の調査では、対象ファイルシステム、業務への影響、削除対象の必要性を確認することが重要である。
