# Linux運用基礎編

Linux Server Operations Lab の一環として、Ubuntu Serverを実際に操作しながら、Linuxサーバの正常状態を確認するための基本的な点検を行いました。

この学習では、コマンドを覚えることだけを目的にせず、

「何を確認するためのコマンドなのか」

「どの結果を見れば正常か判断できるのか」

を意識して実機で確認しています。

---

## 学習環境

検証環境はVirtualBox上に構築しています。

```text
controller
192.168.56.10

tokyo
192.168.56.11

yokohama
192.168.56.12

omiya
192.168.56.13
```

今回の基礎編では、主に `tokyo` サーバを対象に確認しました。

OS：

```text
Ubuntu Server 24.04
```

---

## 今回確認した内容

### 1. ディスク使用量

```bash
df -h
```

ルートファイルシステムの使用率などを確認しました。

総合演習時の `/` の使用率は27%で、ディスク容量に余裕があることを確認しました。

---

### 2. メモリ

```bash
free -h
```

`free` だけではなく、実際に利用可能なメモリを判断するときは `available` も確認することを学びました。

総合演習では、

```text
available: 631Mi
swap used: 0B
```

となっており、大きなメモリ不足は確認されませんでした。

---

### 3. CPU・プロセス

```bash
top
```

CPU使用状況、Load Average、プロセス数、Zombieプロセスなどを確認しました。

総合演習では、

```text
CPU idle: 99.6%
Zombie: 0
```

となっており、CPU負荷が低い状態であることを確認しました。

---

### 4. nginx

まずサービスの状態を確認しました。

```bash
systemctl status nginx
```

続いて、80番ポートが待ち受けていることを確認しました。

```bash
sudo ss -lntp | grep ':80'
```

最後に、実際にHTTP通信を行いました。

```bash
curl -I http://localhost
```

結果：

```text
HTTP/1.1 200 OK
```

この確認から、

```text
サービス状態
↓
プロセス・ポート
↓
実際の通信
```

と段階的に確認することの重要性を学びました。

---

### 5. ネットワーク

IPアドレスを確認しました。

```bash
ip addr
```

今回の環境では、VirtualBox上で複数のネットワークインターフェースを使用しています。

controllerとの疎通確認も行いました。

```bash
ping -c 4 192.168.56.10
```

結果：

```text
4 packets transmitted
4 received
0% packet loss
```

---

### 6. DNS

名前解決が実際にできるか確認しました。

```bash
getent hosts example.com
```

IPv6アドレスが返り、名前解決が正常に行われていることを確認しました。

設定を見るだけではなく、

```text
設定確認
↓
実際に名前解決
```

まで確認することを意識しました。

---

### 7. ログ

nginxのログをsystemd journalから確認しました。

```bash
sudo journalctl -u nginx -n 20 --no-pager
```

過去の停止・起動履歴も表示されました。

ここから、

「ログにエラーや停止履歴がある = 現在も障害が発生している」

とは限らないことを学びました。

現在時刻、サービス状態、実際の通信結果などと組み合わせて判断する必要があります。

---

### 8. ユーザー・グループ

現在操作しているユーザーを確認しました。

```bash
whoami
```

UID、GID、所属グループは次のコマンドで確認しました。

```bash
id
```

今回使用した `tokyo` ユーザーはUID/GID 1000で、`sudo` などのグループに所属していることを確認しました。

---

### 9. sudo

ユーザーに許可されているsudo権限を確認しました。

```bash
sudo -l
```

今回の環境では通常のsudo権限に加えて、

```text
/usr/bin/systemctl restart nginx
```

についてNOPASSWD設定が存在することも確認しました。

---

### 10. SSH

SSHサービスを確認しました。

```bash
systemctl status ssh
```

続いて22番ポートを確認しました。

```bash
sudo ss -lntp | grep ':22'
```

さらにcontrollerから実際にSSH接続し、ログから公開鍵認証が成功していることも確認しました。

確認の流れ：

```text
SSH設定
↓
サービス
↓
22番ポート
↓
実際のSSH接続
↓
認証ログ
```

---

### 11. パッケージ更新

更新可能なパッケージを確認しました。

```bash
apt list --upgradable
```

パッケージ情報を更新しました。

```bash
sudo apt update
```

さらに、実際に変更する前にシミュレーションも行いました。

```bash
sudo apt-get -s upgrade
```

その後、

```bash
sudo apt upgrade
```

を実行しました。

アップデート後に再起動が必要になったため、再起動を実施しました。

---

### 12. 再起動後の確認

再起動前のカーネル：

```text
6.8.0-139-generic
```

再起動後：

```bash
uname -r
```

結果：

```text
6.8.0-146-generic
```

新しいカーネルで起動していることを確認しました。

さらに、

```text
nginx
80番ポート
HTTP 200
SSH
22番ポート
```

などを再確認しました。

単にアップデートコマンドが終了しただけではなく、

```text
アップデート
↓
再起動要否確認
↓
再起動
↓
再接続
↓
カーネル確認
↓
サービス確認
↓
ポート確認
↓
実際の通信確認
```

まで行うことを意識しました。


# 総合演習で分かったこと

実際に何も見ずに点検してみると、理解していてもコマンドをすぐに思い出せないものがありました。

比較的思い出せたもの：

```text
df
free
top
ss
ip
ping
```

復習が必要だと感じたもの：

```text
journalctl
getent hosts
whoami
id
sudo -l
uname -r
apt list --upgradable
```

今回の総合演習を通して、

```text
意味が分かる
↓
コマンドを知っている
↓
必要な場面で思い出せる
↓
結果を読める
↓
状態を判断できる
```

は、それぞれ別の段階だと感じました。

今後も実機操作を繰り返しながら定着させていきます。

---

# 次のステップ

今回の基礎編では、主に「正常なサーバがどのような状態なのか」を確認しました。

次は意図的に安全な範囲で障害を発生させ、

```text
正常状態
↓
障害発生
↓
症状確認
↓
情報収集
↓
原因切り分け
↓
修正
↓
復旧確認
↓
再発防止
```

という流れを実機で検証していく予定です。

その後、手作業で理解した運用手順の中から、繰り返し作業をAnsible・Python・Excelなどで自動化していきます。

# 注意事項

この検証は自宅のVirtualBox環境で実施しています。
